Creator Genie — Product Approach

Task-Based App Creation

Making AI-generated apps that actually work — by making every decision explicit, reviewable, and reversible.

The Problem

One-shot AI generation
produces demos, not tools.

When a user says "build me an inventory tracker," current AI generators make 70+ implicit decisions the user never agreed to.

Root Cause Analysis

Why one-shot fails

Six structural problems, not quality problems.

01
Assumption-heavy
AI guesses fields, relationships, workflows. User never agreed to any of them.
02
No recovery path
70% right + 30% wrong = start over. There is no middle ground.
03
Generic, not contextual
Doesn't know the user has 4,200 contacts in CRM or a custom deal stage.
04
Structural hallucination
Without Creator constraints, AI generates plausible components that don't work.
05
Users prompt poorly
"Build me a vendor onboarding app" is reasonable. It's a terrible generation prompt. Our gap to close.
06
Patience is finite
~90 seconds of trust. Miss the window and the user leaves. Forever.
Alternatives Considered

What we evaluated and rejected

×
"Just make one-shot generation better"
Even at 95% accuracy, 5% wrong in a 20-component app = 1 broken thing the user can't fix. The problem isn't generation quality — it's the interaction model.
×
"Build a chat-first app builder"
Chat is linear; apps are structural. A user describing a 12-field form in chat loses track by field 8. Chat creates an illusion of understanding without verification.
×
"Focus on templates with AI customization"
Templates get to 60% fast, but the last 40% — where all the business-specific value lives — requires the editing skills the user doesn't have.
×
"Build an AI coding assistant"
Different persona entirely. Our target user doesn't want to see code. They want to describe a business outcome and get a working tool.

Conversation Strategy

3 turns. Not 30.

Assume boldly, show transparently. Don't ask what you can reasonably infer.

1
Reflect & Assume
AI mirrors back what it heard, makes bold assumptions about users, workflows, data. Shows assumptions as an editable checklist. Asks 1–2 questions max.
→
2
Refine
User corrects what's wrong, confirms what's right. AI updates understanding, asks 1 remaining critical question if needed.
→
3
Converge
Brief confirmation of final understanding. "Ready to plan" button appears. Understanding panel is complete.

Scope

What we are NOT building (V1)

Deliberate exclusions with clear rationale.

No Undo
Forward-only correction. "That's wrong, change it to X" is more natural than "revert to before." Undo in a stateful system with live components is extraordinarily complex.
No Concurrent Editing
Expected usage: trigger Genie, wait, review. Concurrent editing is an edge case for v1. Last-write-wins at execution time.
No Zia Integration
Dependency on another team's release cycle is unacceptable for v1 velocity. Integration later is possible; coupling now is expensive.
No Code Exposure
User never sees Deluge. Period. Workflows are described in plain English. Changes via natural language, not code editing.
No Multi-App
One app at a time. "Build me a suite" gets guided toward "Let's start with one." Cross-app orchestration is out of scope.

Open Questions

What we know
we don't know yet

1
What is the right fidelity for the plan?
Hypothesis: 1-sentence task description + bullet list of specifics. Total plan fits one screen. Needs user testing.
2
How do we handle tasks that fail during execution?
Hypothesis: Pause sprint, surface plain-language explanation, let user retry/skip/modify. Needs error taxonomy from engineering.
3
Where does context window size become a constraint?
Hypothesis: Sprint-based execution naturally manages context. Needs engineering spike for max-complexity app.
4
What happens when the user's Zoho data is messy?
Hypothesis: Flag data quality issues during planning. Needs analysis of real org data patterns.
